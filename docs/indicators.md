# Indicators

DevTrace generates two indicators. Each is a single, static SVG card built from a JSON file; see
[configuration](configuration.md) for the files and [customization](customization.md) for the look.

> Each indicator also has a multi-panel dashboard: see [Startup & SaaS](startup-dashboard.md),
> [AI Engineering](ai-engineering-dashboard.md) and [Developer Activity](developer-activity-dashboard.md).
> To use the files in your profile, see [github-profile.md](github-profile.md).

## Startup & SaaS Statistics

### What the indicator displays

A single card with:

- **Summary:** Total Projects, Active Projects and Launched Projects.
- **Lifecycle:** one horizontal bar per lifecycle stage that has projects.
- **Projects:** name, lifecycle stage, operational status and, optionally, a `repo` / `site`
  indicator (the URLs themselves are never rendered).
- **Footer:** `Generated by DevTrace v<version>`.

Definitions (public projects only):

| Metric             | Meaning                                          |
| ------------------ | ------------------------------------------------ |
| `totalProjects`    | Number of public projects                        |
| `activeProjects`   | Public projects with status `ACTIVE`             |
| `launchedProjects` | Public projects in stage `LAUNCHED` or `GROWING` |

### Configuring `data/startup.json`

```json
{
  "version": 1,
  "profile": { "displayName": "Developer Portfolio" },
  "settings": {
    "theme": "DARK",
    "showProjectList": true,
    "showLifecycleDistribution": true,
    "showLinks": true
  },
  "projects": [
    {
      "id": "my-app",
      "name": "My App",
      "description": "What it does.",
      "category": "SaaS",
      "lifecycleStage": "MVP",
      "status": "ACTIVE",
      "visibility": "PUBLIC",
      "dataSource": "DECLARED",
      "repositoryUrl": "https://github.com/username/my-app",
      "createdAt": "2026-01-01",
      "updatedAt": "2026-02-01"
    }
  ]
}
```

- `version` is required and must be `1`. `profile` and `settings` are optional; omitted values
  use the defaults shown above (`theme` is `DARK` or `LIGHT`).
- **Lifecycle stages:** `IDEA`, `RESEARCH`, `PROTOTYPE`, `MVP`, `DEVELOPMENT`, `LAUNCHED`,
  `GROWING`, `MAINTENANCE`, `ARCHIVED`.
- **Operational statuses:** `ACTIVE`, `PAUSED`, `INACTIVE`. Status is independent from the
  lifecycle stage.
- The file is validated before anything is generated. Invalid data produces an error and no file
  is written. See [data-model.md](data-model.md).
- The shipped file lists only the DevTrace project itself. Replace it with your own projects.

### Privacy behavior

The SVG is meant to be committed to a public repository, so:

- Projects with `"visibility": "PRIVATE"` are removed **before** statistics are computed. They are
  not counted and their names, descriptions, categories and links never reach the SVG.
- `visibility` is required on every project, so nothing becomes public by omission.
- Descriptions and URLs are never rendered, even for public projects.

### Generating the SVG

```bash
pnpm generate:startup
```

Writes `public/indicators/startup-stats.svg` and prints a success message. The command only
writes that one file.

### Embedding in a GitHub README

Commit the generated SVG, then reference it:

```html
<img
  src="https://raw.githubusercontent.com/<username>/<repository>/HEAD/public/indicators/startup-stats.svg"
  alt="Startup & SaaS Statistics"
/>
```

## AI Engineering Statistics

### What the indicator displays

A card with the same layout and themes as the Startup card. A **summary** of AI Tools, AI Models,
AI Skills and AI Projects is always shown. Optional sections, each controlled by a setting:

| Section     | Content                                                  | Setting                     | Default |
| ----------- | -------------------------------------------------------- | --------------------------- | ------- |
| Providers   | Distinct provider names across public tools and models   | `showTools` or `showModels` | on      |
| Tools       | Name, category, provider                                 | `showTools`                 | on      |
| Models      | Name, model family, provider                             | `showModels`                | on      |
| Skills      | Grouped by category, with the **declared** level         | `showSkills`                | on      |
| Projects    | Name, status, techniques and a `repo` / `site` indicator | `showProjects`              | on      |
| Activity    | Declared records: type, AI involvement, date, provenance | `showActivity`              | off     |
| Token usage | Reported values with period, provenance and source       | `showTokenUsage`            | off     |

Sections without public data are omitted. If nothing can be shown, the card says
`No AI engineering data to display.`

### Providers, products and models

These are different things and are stored separately:

- **Provider:** who offers it (for example `Anthropic`). It is an attribute of a tool or model.
- **Tool (product):** what you use (for example `Claude Code`), with a category such as
  `AI_ASSISTANT`, `IDE_ASSISTANT`, `API_PROVIDER`, `AGENT_FRAMEWORK`, `DEVELOPMENT_TOOL` or
  `MODEL_PLATFORM`.
- **Model:** a specific model (for example `Claude Sonnet`) with its `modelFamily` (`Claude`).

Nothing is listed unless you declare it. The names above are only examples.

### Skills

Skills have a category (`LLM_ENGINEERING`, `AI_AGENTS`, `RETRIEVAL_KNOWLEDGE`,
`AI_SYSTEM_DESIGN`) and a proficiency level: `EXPLORING`, `LEARNING`, `PRACTICING`, `PROFICIENT`
or `ADVANCED`. Levels are **your own statements**, not certifications or measurements. DevTrace
never derives a level from the tools you use and has no scores, rankings or percentages.

### AI projects

Projects have a status (`ACTIVE`, `PAUSED`, `INACTIVE`), techniques (`RAG`, `AI_AGENTS`,
`FUNCTION_CALLING`, `TOOL_USE`, `LLM_INTEGRATION`, `VECTOR_SEARCH`, `PROMPT_ENGINEERING`) and
references to your tools by ID. They are a separate model from the startup projects because the
fields differ; visibility, provenance, status and URL rules are shared.

### Activity tracking

Activity records are entered manually; there are no integrations with Copilot, Cursor or GitHub.
Each record states its `involvement`, so the card never blurs the difference between
`AI_ASSISTED`, `AI_GENERATED` and `AI_RELATED_ENGINEERING` work. An AI-related project does not
create activity, and DevTrace shows the records you provide instead of a contribution count.

### Token usage limitations

Token and cost metrics are values you report; DevTrace measures and calculates nothing.

- Each metric belongs to a model (`modelId`) and has a measurement period.
- Token metrics must use the unit `TOKENS` and whole numbers. Cost metrics
  (`ESTIMATED_COST`) use an ISO 4217 currency code such as `USD`.
- Values are never summed, converted or inferred from prompts, commits or activity.
- Costs are financial data and are hidden unless `showCost` is `true` (and `showTokenUsage` too).
- An `OBSERVED` metric must name a `source`.

### Data provenance

Every tool, model, skill, project, activity and metric has a required `provenance`:
`OBSERVED` (from a verifiable source), `DECLARED` (stated by you) or `ESTIMATED` (inferred from
incomplete data). It is the same concept as `dataSource` in the startup file. Activity and token
rows show their provenance on the card, so estimated values are not presented as observed.
Today every value is entered by hand, so `DECLARED` is the honest choice unless you have a source.

### Privacy behavior

Every entity has a required `visibility` (`PUBLIC` or `PRIVATE`). Private entities are removed
**before** statistics are computed, so they affect no total, grouping or provider count. Entities
that would reveal a private one are removed too:

- an activity linked to a private project,
- a token metric whose model is private,
- cost metrics unless `showCost` is enabled.

Descriptions of projects and skills and all URLs are never rendered (only a `repo` / `site`
indicator). Activity descriptions are rendered for public records, so keep them non-sensitive or
mark the record `PRIVATE`.

### Configuring `data/ai-engineering.json`

The shipped file has empty lists, so nothing is claimed on your behalf. Settings and lists may be
omitted; omitted settings use the defaults shown. A fuller example (placeholder values):

```json
{
  "version": 1,
  "profile": { "displayName": "AI Engineering Profile" },
  "settings": {
    "theme": "DARK",
    "showTools": true,
    "showModels": true,
    "showSkills": true,
    "showProjects": true,
    "showActivity": false,
    "showTokenUsage": false,
    "showCost": false,
    "showLinks": true
  },
  "tools": [
    {
      "id": "my-assistant",
      "name": "My Assistant",
      "provider": "Example Provider",
      "category": "AI_ASSISTANT",
      "visibility": "PUBLIC",
      "provenance": "DECLARED"
    }
  ],
  "models": [
    {
      "id": "my-model",
      "name": "My Model 1",
      "provider": "Example Provider",
      "modelFamily": "My Family",
      "visibility": "PUBLIC",
      "provenance": "DECLARED"
    }
  ],
  "skills": [
    {
      "id": "prompt-engineering",
      "name": "Prompt Engineering",
      "category": "LLM_ENGINEERING",
      "proficiencyLevel": "PRACTICING",
      "visibility": "PUBLIC",
      "provenance": "DECLARED"
    }
  ],
  "projects": [],
  "activities": [],
  "tokenUsage": []
}
```

The file is validated before anything is generated: unknown fields, invalid enum values,
duplicate IDs, malformed URLs and references to unknown IDs produce an error and no file is
written. See [data-model.md](data-model.md) for every field.

### Generating the SVG

```bash
pnpm generate:ai
```

Writes `public/indicators/ai-engineering-stats.svg` and prints a success message. Generating the
AI indicator does not touch the startup one.

```html
<img

  alt="AI Engineering Statistics"
/>
```
